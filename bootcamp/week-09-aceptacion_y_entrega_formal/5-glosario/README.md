# 🎓 Glosario — Semana 9

| Término | Definición breve |
|---|---|
| **Pruebas de aceptación (UAT)** | Pruebas que ejecuta el cliente para decidir si el software sirve para lo que pidió |
| **Requisito** | Necesidad acordada con el cliente que el software debe cumplir |
| **Caso de aceptación** | Prueba de un requisito en formato *Dado / Cuando / Entonces* |
| **Criterio de entrada** | Condición para empezar las pruebas de aceptación |
| **Criterio de salida** | Condición acordada para aceptar el software |
| **Severidad** | Gravedad de un defecto: bloqueante, mayor, menor, cosmético |
| **Aceptado con observaciones** | Aceptación con defectos menores y fechas de corrección |
| **Consolidación** | Unir las secciones del plan en un documento coherente y versionado |
| **Simulacro cruzado** | Otro equipo instala y restaura el proyecto usando solo el plan |
| **Gate** | Condición obligatoria para aprobar: si no se supera, no se acepta |
| **Servidor limpio** | Servidor sin restos de instalaciones previas del proyecto |
| **Paquete de entrega** | Plan, respaldo cifrado y huella que recibe el equipo que instala |
| **Observador** | Quien registra el simulacro sin ayudar |
| **Desviación** | Diferencia entre lo que dice el plan y lo que se tuvo que hacer |
| **Acta de entrega** | Documento con el que el cliente recibe formalmente el software |
| **Nivel de servicio** | Compromiso medible: disponibilidad, tiempos de respuesta, RPO/RTO |
| **Transferencia de accesos** | Entregar al cliente el control de cuentas, servidores y secretos |
| **Garantía** | Periodo en que el equipo corrige defectos sin costo |
| **Socialización** | Presentación de los resultados a interesados |
| **Lecciones aprendidas** | Registro de qué funcionó, qué no y qué cambiar la próxima vez |
